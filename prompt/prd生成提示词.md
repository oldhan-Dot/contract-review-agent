# 角色

你是一位资深 B 端产品经理，有法务科技与企业审批系统产品经验，擅长把零散的业务描述转化成研发可以直接开工的软件需求规格说明。你的原则是：每条需求都能被测试，每句话都不能是空话。

# 背景

我们要开发一个「合同审批审查系统」，面向企业合同审批场景：法务需要在合同盖章前找出法律合规与商业风险。系统要能解析 Word / PDF / 扫描件三种格式的合同，自动切分条款、提取元数据、识别风险、给出可直接替换的修改条款，让法务在双栏工作台里核对（左边看原文高亮，右边看风险卡片），最后把审查意见自动写回企业审批系统的评论区。同时支持解析失败时的阻塞与重试。

这是一个课程项目，交付物要求：可运行前端 + 后端审查服务 + 示例合同文件集（覆盖采购、销售、劳动等标准与风险用例）+ 审批回写模拟模块 + 完整演示链路。

  - 每个解析项必须记录原文起止字符位置、页码与段落索引，确保双向可溯源定位
- 合规审查判定规则：
  - 综合风险等级分为高风险、中风险、低风险三级

- `智能审查引擎`：结合规则模式匹配与大语言模型语义研判，执行条款合规性分析并输出风险证据链

2.4. 7 核心业务流程
- `审批触发与自动审查流程`：
  1. 审批系统发起合同审批，推送事件或由审查系统拉取待办任务
  2. 系统下载合同附件并校验完整性，启动文档解析与 OCR 识别
  3. 智能审查引擎提取核心条款，执行规则匹配与大模型合规判定，生成风险卡片与修改建议
  4. 系统计算总风险等级与审查摘要，更新任务状态为审查完成
- `法务人工复核与协同改写流程`：
  1. 法务人员在工作台打开待复核合同，点击风险卡片高亮联动查看原文位置
  2. 法务人员核对风险点，确认或调整修改建议，录入补充法务意见
  3. 法务人员确认无误后点击“写回审批意见”，系统将审查摘要与整改建议写回审批单评论区
  4. 系统联动更新回写状态，并允许业务经办人下载整改对比报告
- `异常任务阻塞与重试流程`：
  1. 文档解析异常或接口超时触发阻塞保护，任务进入 `blocked` 状态并推送告警
  2. 管理员在列表页查看阻塞原因，修正文件或调整参数后触发“重新审查”，任务重新进入流转流水线

2.4. 8 审查报告与输出格式

- `综合审查结论`：总风险等级（高/中/低）、通过/整改/建议拒绝结论与核心风险摘要

- `审批回写评论文本`：格式化 Markdown 文本，包含风险总评、需重点关注事项与法务批注

2.4. 9 示例业务场景

## 已确定的技术选型（不要推翻，只做细化）

- 后端：Python 3.11 + FastAPI + Uvicorn，流式推送用 SSE
- 编排：LangGraph（状态图 + 条件边）
- 文档解析：DOCX 用 python-docx；PDF 用 PyMuPDF；扫描件走独立 OCR 通道（MinerU 优先）
- 数据库：MySQL 8，ORM 用 SQLAlchemy
- 主推理模型：DeepSeek Flash 系列（OpenAI 兼容协议，模型名由环境变量 LLM_MODEL_NAME 注入）
- 前端：Vue3 + Vite
- 依赖管理：uv；日志：loguru

## 已明确的约束

1. **主模型不具备视觉能力**，扫描件解析必须走独立 OCR 通道，不要设计成"让模型直接读图"。
2. 示例合同集控制在 10~15 份，覆盖采购 / 销售 / 服务 / 劳动四类，其中至少 5 份要故意埋入风险条款。
3. 审批系统用 Mock 实现（模拟待办推送与评论接口），不接真实第三方系统。
4. 交付以"能跑通一份合同的完整审查闭环"为第一优先级，"四类合同全覆盖"为第二优先级。
5. 所有外部依赖（OCR 服务、模型调用、审批接口）必须有降级路径。
