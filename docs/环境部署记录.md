## 与设计文档的环境差异

- DaoCloud 镜像源返回 502，使用官方 `mysql:8.0.36` 成功部署。
- MySQL 数据使用 Docker 命名卷，代替 Windows 项目目录绑定卷。
- 本机已安装 Node 24，直接复用并通过构建验证，没有全局切换 Node 版本。
- Vue 3.4 与较新 Vue Router / Pinia 的 peer dependency 不兼容，锁定兼容版本，没有使用强制忽略依赖检查。
- 技术方案实际 DDL 包含 21 张表，按完整 DDL 部署。
- 新增 `LLM_ENABLED=0` 作为环境准备阶段的显式开关；启用后仍要求配置密钥。
- 任务并发默认 5，与 PRD 的并发容量要求一致；当前业务 worker 尚未实现。

## 待配置与待开发

初次部署时模型与 MinerU 默认关闭。现在已将用户提供的 MinerU 云 API 根地址 `https://mineru.net/api/v4` 和 Token 配置到本地 `.env`，并启用 `MINERU_ENABLED=1`。Token 不写入文档或版本管理。模型配置仍按实际服务信息填写。

模型健康检查仅验证 `/models` 可达性、认证和模型 ID，不代表推理质量验收。MinerU 云 API 的 `MINERU_HEALTH_PATH` 留空，健康检查明确返回 `unverified`；后续接入解析模块时再验证 Token 有效性、任务提交和结果获取。

配置与代码统一采用 `MINERU_` / `mineru_` 命名；健康响应中的服务字段改为 `mineru`，前端同步使用新字段。PRD 中 OCR 仍表示文字识别能力，相关业务错误码和算法概念保留。

本次交付为开发环境与启动骨架。审查规则、模板、示例合同、合同解析业务管道、LangGraph 审查编排、审批 Mock 业务接口及完整页面交互尚未实现，健康检查会明确显示相应状态。

启动和停止方法见根目录 `README.md`。不要将 `.env` 或真实密钥加入版本管理。
