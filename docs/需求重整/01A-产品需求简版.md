## 1. 做什么，给谁用

用户提交一份合同，系统提取信息、发现风险、给出修改建议；法务核对原文并确认意见，再回写审批单、导出报告。

| 角色 | 主要操作 |
|---|---|
| 业务经办人 | 上传合同、查看处理状态和风险、下载报告 |
| 法务审查人 | 核对证据、修改和采纳建议、填写批注、确认回写 |
| 系统管理员 | 维护规则/模板及对接参数，处理阻塞任务与重试 |

已确认：业务只看本人任务；法务查看并复核全部送审任务；管理员维护配置与重试，不能代替法务确认。系统提供辅助意见，最终审批决定由人作出。

## 2. 最终必须具备哪些功能

| 能力 | 必须做到什么 |
|---|---|
| 合同接入 | 本地上传及模拟审批待办接入，附件校验与去重 |
| 文档解析 | DOCX、文本 PDF、扫描件/图片都能成功解析；不是只返回失败提示 |
| 信息结构化 | 提取主体、金额、币种、期限、生效条件等，切分和归类主要条款，记录原文位置 |
| 风险审查 | 规则与模型结合，识别主体、付款、责任、知识产权、管辖等风险及必备条款缺失，输出等级、成因和依据 |
| 修改建议 | 结合标准示范条款库生成替代文本，支持原文/建议对照、复制、编辑、采纳和人工确认 |
| 审查工作台 | 分页阅读原文、字段与风险高亮、原文和卡片双向定位，展示摘要和法务批注 |
| 任务流转 | 处理进度、失败原因、修正/重传及重试，明确区分任务状态和回写状态 |
| 审批与报告 | 法务确认后回写模拟审批评论；提供 Markdown、PDF 两种报告 |
| 管理与列表 | 大盘筛选、批量操作、按合同类型维护规则条件/等级/启停及示范条款 |
| 演示与验收 | 提供标准和风险样例，覆盖原始验收；至少一个典型场景完整演示 |

不要求先建设通用规则语言、向量数据库、微服务或真实企业审批厂商集成。示范条款库仍须存在，其技术形式放到 spec 决定。规则和样本按风险与场景覆盖安排，不沿用旧文档固定数量。

## 3. 用户怎样完成一次审查

**上传合同或接收审批待办 → 解析与信息提取 → 规则/模型审查 → 展示风险及修改建议 → 法务核对原文、编辑确认并批注 → 回写关联审批单 → 导出报告。**

主要页面只有三个：**合同大盘、审查工作台、规则与模板管理**。

需要记住的行为：

- 我方是甲方还是乙方、合同类型和主体性质会影响判断，不能一律默认。
- 已确认送审必填文件、合同类型、我方甲/乙角色，申请人取当前身份；主体名称和金额先提取，缺失再提示。批量操作先做管理员重试、用户导出有权查看的报告。
- 字段或条款缺失时明确提示，不编造原文位置；企业信用未核实不能显示为正常。
- 已确认模型审查失败先有限自动重试，仍失败则受阻，保留规则结果；仅建议生成失败可重试或由法务补充后确认。
- “审查完成”不等于“法务确认”或“审批通过”。只有法务确认且关联审批单，才能回写。
- 重审后需重新核对当前结果；不能直接沿用旧确认。重复回写相同意见应避免重复评论。
- “违约金 20%”等原始示例不是通用法律常量；风险依据与阈值要有来源。

## 4. 分几步做，怎样算完成

所有阶段完成后才是原始要求的完整交付。阶段表示顺序，不代表后续能力可取消。

| 阶段 | 重点 | 完成标志 |
|---|---|---|
| A：审查主链 | DOCX、核心信息、规则与模型、建议、基础工作台 | 上传一份 DOCX 后能看到实际审查结果、证据和建议，失败可见 |
| B：格式与定位 | PDF、OCR、分页预览、双向高亮与重试 | 三类格式均有成功用例，卡片与原文双向定位正确，异常可恢复 |
| C：复核与管理 | 权限、法务编辑确认、批注、规则/模板维护、批量操作 | 保存后刷新仍存在；管理变更影响后续审查，权限操作可验证 |
| D：完整交付 | 审批 Mock、回写、两种报告、样例与联调 | 至少一个典型场景贯通拉取、审查、复核、回写与报告导出，原始八项验收逐项通过 |

实现仍按一个模块一个模块推进。A 阶段即需示范模板及测试样例，格式和分页也可以提前试验，避免最后才发现技术不可行。

目前已经有上传后端、DOCX 解析、结构化节点及审查数据结构，实际规则/模型审查和完整业务页面尚未接通。已有模块先保留，是否符合新约定需另行核对，不能算 A 阶段已完成。

## 5. 已确认方向，哪些还需验证

| 事项 | 当前决定及后续工作 |
|---|---|
| 规则、依据与条款库 | 使用有来源的资料，区分法律、企业要求和谈判建议；具体样例仍需收集核验 |
| 企业异常数据 | 演示先用明确标注的模拟数据，无结果显示未核实 |
| Word 分页 | 用户协助提供开发试验用转换 PDF；保留原件并核验排版/位置映射，最终产品转换方式仍待定，不阻塞先写 spec |
| 真实模型审查 | 用真实合同验证输出和证据；不把服务已配置当成效果已通过 |
| 环境与样本 | 当前 Windows 开发机和固定浏览器；先覆盖采购/销售/劳动正常与风险、各格式及异常，同一文件可覆盖多项 |
| 性能与时间 | 实测后确定目标和排期，浏览器版本在试验时记录，不承诺固定工时、样本总数或准确率 |
