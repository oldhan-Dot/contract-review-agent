# 模块 09：条款切分器

> 模块开发记录，保留当时的实现与验证状态。当前需求以 [PRD](../PRD.md) 为准，技术实现以 [Spec](../SPEC.md) 为准；历史章节号不作为当前规范。

新增 `app/structuring/splitter.py`，入口为 `split_clauses(document)`，读取解析结果 `ParsedDocument`，返回 `list[Clause]`。本模块不查询数据库，不调用模型服务，也不执行条款归类或字段提取。

## 主要流程

1. 优先选择一个主策略：编号 → 标题样式 → 伪标题 → 自然段。
2. 按选中的边界把段落分组，生成条款编号、层级、正文和原文区间。
3. 正文超过 3000 字符时，优先沿句末或段末切分成不超过 800 字符的子区间；没有标点的长句按长度兜底。
4. 检查条款与原文一致、顺序号连续、父记录存在，且主条款和长条款子区间没有遗漏正文。

同一份文档只采用一种主策略，长度兜底可用于该策略下的超长条款。编号策略支持「第一条」「第三条之一」「1.1」「1.1.1」「（一）」「(1)」「【第三条】」等形式；前导空白保留在原文区间，编号本身不进入审查正文。

标题样式使用解析得到的 `heading_level`。伪标题采用短段加粗或冒号结尾的线索；无结构线索时按自然段切分。表格中的文本保持解析顺序；不因 PDF 分页而切开同一条款。条款主类型仍为 `OTHER`，需要后续归类模块填充。

## 超长条款的父子关系

返回列表保留超长父记录，并追加 `parent_index` 指向它的子条款，子条款具有 `part_no`、`level=0` 和独立原文区间。父记录用于追溯完整来源；后续审查应使用子条款，避免同一内容重复送审。

可以这样选出待审查条款，普通编号层级的父条款不会被误删：

```python
split_parent_indexes = {c.parent_index for c in clauses if c.part_no is not None}
review_clauses = [c for c in clauses if c.index not in split_parent_indexes]
```

父记录的原文区间覆盖全部内容；子区间可以排除边界空白，但不允许遗漏非空白正文。条款顺序号仍从 1 开始且连续，子条款引用的父记录一定存在于返回列表。

## 文档差异处理

- PRD FR-204 要求两个编号条款也能切分，因此不采用技术示例的「至少三个编号/标题命中」门槛。
- `1.1`、`1.2` 按 PRD 验收设为一级；三级点号形式 `1.1.1` 为二级。技术示例中的层级口径不同，本实现优先采用 PRD。
- 技术示例移除超长父条款后仍引用它，可能形成不存在的父记录。本实现保留父记录，并明确后续审查排除这些长条款父记录。
- 不静默过滤短句或只有编号的段落，避免「应付款」「不得转让」等短义务丢失；编号单独一段时与其后正文合并。

无正文抛出 `ParseBlocked("EMPTY_BODY", ...)`，但本模块不更新数据库任务状态；执行器和 `structure_document` 节点仍待接入。
