# 29 — PNG/JPEG 图片上传与审查

日期：2026-10-15。需求见 [PRD](../PRD.md)，技术实现见 [Spec](../SPEC.md)。本模块未提交/推送。

## 本次完成

支持 PNG、JPG、JPEG 单张图片直接上传，保留原始字节、扩展名和正确 MIME。图片按一页合同接入 MinerU OCR、条款/字段、规则与模型审查，并提供受保护原件预览、风险框和字段定位。

[合成 PNG 任务 489](http://127.0.0.1:5173/tasks/489) 已实际 completed，来源 IMAGE_OCR、1 页、2 个条款。图片由合成 PDF 的一页渲染得到，不是真实合同；已发送至配置的 MinerU 和模型服务。

本版一次一张图片，不会自动把多张照片合并成同一合同。需要多页时可先整理为 PDF；多图合并作为后续扩展，不将其算作本次已交付。

## 核心处理方式

原图 → 校验格式/像素数 → 按方向/DPI 转成内部单页 PDF → 已验证的 MinerU 上传/轮询协议 → IMAGE_OCR IR → 原有结构化和审查流程。

内部转换只用于 OCR 和预览坐标统一，不替换用户原件、不创建第二个任务，也不等于实现了 Word 转 PDF。JPEG 的 EXIF 方向由同一 PyMuPDF 转换路径处理，预览和 OCR 使用一致的显示方向。

| 文件 | 变化 |
|---|---|
| app/parsing/image_channel.py | 校验 PNG/JPEG，处理单图方向/DPI，保存内部 PDF 并复用 OCR |
| app/api/tasks.py | 图片入口、真实格式/体积校验、正确 MIME、保存原件及去重 |
| app/graph/nodes/parse_document.py | png/jpg/jpeg 分派到 parse_image |
| app/structuring 与结构化节点 | 接受 IMAGE_OCR，复用字段/条款和块级 Anchor |
| app/services/pdf_preview.py、页图接口 | 原图哈希和权限/版本保护；使用相同转换方法提供单页预览 |

| app/services/reports.py | 报告保留解析来源、识别警告、字段核对提示和证据页码 |

## 上传与文件边界

- 支持扩展名 png/jpg/jpeg，大小仍受 50MB 配置限制；图片不套用 DOCX 的 1KB 下限。
- 不信任客户端 MIME，先读 PNG/JPEG 头验证格式/尺寸，再用库解码验证可读性。扩展名与真实内容不符返回 415。
- 解码前限制不超过 2500 万像素，避免极大位图耗尽内存；超出返回 413。这个限制是首版资源边界，不是 OCR 准确率指标。
- 原件和内部派生 PDF 分开保存；内部件按原图 SHA-256 存于 data/renders/images，重审可复用。
- 当前仅普通 PNG/JPEG；不支持 HEIC、TIFF、GIF、动画或多帧图片。拍摄缺页、裁切、反光和严重模糊仍需人工核对。

## 位置与结果

单图在统一 IR 中用 page_no=1 表示。内部 PDF 的页面单位由转换结果确定，MinerU 的归一化框按同一页面尺寸转换；前端继续使用百分比框，不直接混用照片像素和 PDF point。

source_format=IMAGE_OCR、channel=ocr。坐标精度仍为 OCR 内容块，不虚构字符级框或置信度；来自 OCR 的 Anchor 标记 OCR_BOX。

OCR 数字空格保护继续生效，不能把分散数字当作标准金额。报告加入来源和核对提示，不能让页面上的不确定性在导出后消失。真实合同仍需要法务核对原图。
