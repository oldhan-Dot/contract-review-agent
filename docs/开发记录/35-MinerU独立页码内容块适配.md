# 35. MinerU 独立页码内容块适配

2026-10-16，扫描 PDF 任务 500 多次停在 OCR_RESULT_INVALID，界面显示“文字、页码或位置无法与原件对应”。

## 实际原因

通过已缓存的 MinerU 返回结果本地复现，未发送云请求。三页数量一致、页码范围正确、归一化坐标均合法，布局页尺寸与原 PDF 的差值也在已有容差内。

失败发生于 `app/parsing/ocr_channel.py` 的 `_text`：缓存中含 `text` 与 `page_number` 两类内容块，代码没有支持独立页码 `page_number`，抛出 Unsupported content type 后被外层统一转为“位置无法对应”。因此是返回协议适配遗漏，不能据此认定原件损坏、MinerU 解析失败或网络问题。

## 修复与验证

将 `page_number` 按普通文字内容块处理，保留返回的文字、页码、坐标，沿用原有全文字符区间及位置校验；其他未知类型仍拒绝，不静默忽略正文。

增加独立页码回归用例，检查原文、归一化坐标和段落字符区间；既有协议和异常测试继续运行。Ruff 通过。用任务 500 现有缓存转换成功，得到三页、40 段、约 1800 字。没有重新上传、没有调用模型，也没有自动重审用户任务。

后端自动重载后，用户可由管理员点击“重新审查”，解析阶段复用现有 MinerU 缓存，再进入后续结构化和模型审查；旧失败状态不会仅因代码修复而自动变为成功。未提交或推送 Git。
