# 34. 身份切换返回大盘与模型超时排查

日期：2026-10-16。

## 身份切换

原先右上角选择身份仅调用 `setIdentity`，当前路由保持不变。RouterView 虽会按新用户 ID 重建、请求会使用新身份，但用户仍停留在原合同详情或规则页，容易误认为没有切换。

`frontend/src/App.vue` 增加 `switchIdentity`：选中新身份后更新本地身份，再用 `router.replace('/')` 返回合同大盘。保留原有用户 ID 作为组件 key，大盘重新加载新身份有权查看的任务。选择同一身份不重复跳转。后端任务权限检查保持原样。

实际 Edge 浏览器检查通过：业务详情切法务回到法务大盘；法务详情切管理员回到管理员大盘；管理员规则页切业务回到业务大盘，规则导航消失。任务列表均重新加载，运行时异常为 0。切换身份仍会离开当前页面，建议先保存未完成的意见。

## DOCX 任务超时

用户任务 498 的 DOCX 已解析成功，正文约 1800 字、15 个条款单元，规则结果已保存；失败发生于模型阶段。日志记录 ReadTimeout，没有将上传/解析失败误当成网络问题。

检查发现 `.env` 设置 90 秒，而运行中后端仍使用 25 秒、额外重试 1 次。运行时可能沿用旧进程配置或启动环境覆盖，不能只看 `.env` 判断实际值。

`app/api/workspace.py` 增加只读非敏感字段 `llm_timeout_seconds` 和 `llm_max_retries`，用于核对当前后端实际生效配置，不暴露密钥、服务地址或合同正文。最初通过该接口实际确认读取超时为 25 秒。

用户明确要求由助手执行重启后，核实进程路径、Uvicorn 命令及父子关系，停止本项目旧后端及重载子进程，前端和数据库保持运行。以 `LLM_ENABLED=1`、`LLM_TIMEOUT_SECONDS=90` 在 8000 重启，接口确认后台执行器正常且实际超时为 90 秒。

确认任务 498 为已授权的合成测试原件、没有人工编辑后重试。版本从 2 变为 3，约 43 秒完成，状态 completed，风险 6 项；未代替法务确认或回写审批意见。

本次超过旧 25 秒但在 90 秒内成功，说明旧等待时间不足以完成这次响应。ReadTimeout 表示等待响应数据超时，可能与服务生成耗时或传输停顿有关，不足以独立证明断网，也不保证今后绝不超时。
