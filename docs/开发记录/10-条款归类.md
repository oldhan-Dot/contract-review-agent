# 模块 10：条款归类

新增 `app/structuring/classifier.py` 和 `clause_keywords.py`，读取切分后的 `list[Clause]`，返回填写了类型、置信度和判定依据的新条款列表。本模块不改变原文区间、不写数据库、不执行风险审查；`structure_document` 节点仍待接入。

## 归类顺序

1. 标题优先：明确标题的关键词权重加倍，唯一最高分满足门槛时判定类型。「定义与解释」「通知与送达」等通用章节及其子条款保持 `OTHER`。
2. 正文加权：按照 PRD 8.1，主类型词 3 分、次类型词 2 分、弱词 1 分；一个词在同条款重复出现只计一次。最高分至少 3 且没有并列时判定主类型；次高分相差不超过 1 时记录次类型。
3. 父类型继承：子条款没有明确标题时，默认继承可信父类型，自己的正文唯一最高分更高时可覆盖。父记录必须存在并先于子条款。
4. 规则无法确定时调用可选的外部兜底；未接入、失败或输出不合法时保留 `OTHER`，记录原因和待补判标记。

`PARTY_INFO` 的「甲方」「乙方」在正文中需要主体声明线索（例如「甲方：某公司」）才计分；普通义务中的甲乙方指代不单独证明主体定义。这是针对 PRD 词表的上下文细化，避免付款、保密等普通条款被高频角色名带偏。「主体信息」等明确标题也可判为主体类。

本实现为关键词规则，无法完全理解语义。例如含多个主题的条款可能得分并列，需要后续模型或人工确认；不会通过类型排序强行选择结果。置信度是规则分数的启发式映射，不代表已测量的正确率。

## 写入条款的字段

- `clause_type`：唯一主类型，使用已有十二类及 `OTHER`。
- `clause_type_secondary`：仅作辅助说明，不产生第二条条款记录。
- `type_confidence`：本次规则/兜底判定置信度。
- `classify_rule_hit`：JSON 字符串，记录方法、关键词、各类型分数、父类型来源、未判定原因及 `needs_fallback` 标记。

判定方法包括 `title`、`keywords`、`parent`、`general_title`、`general_parent`、`fallback` 和 `unresolved`。分类器返回新对象，不直接修改输入，其他编号、正文和定位字段保持原样。

## 调用方式

```python
from app.parsing.docx_channel import parse_docx
from app.structuring.splitter import split_clauses
from app.structuring.classifier import classify_clauses

document = parse_docx("data/samples/采购合同.docx", file_id=1)
clauses = classify_clauses(split_clauses(document))
for clause in clauses:
    print(clause.index, clause.clause_type.value, clause.classify_rule_hit)
```

`clause_keywords.py` 是归类词表，不是审查风险的规则库。后续风险规则仍按技术方案从 `sql/seed/rules.yaml` 导入。

## 模型兜底入口与当前限制

可通过 `classify_clauses(clauses, fallback=...)` 传入归类函数，它接收单个条款副本，返回 `{"clause_type": "PAYMENT", "confidence": 0.8}` 这样的结构。规则有明确结果时不会调用它。类型、字段和置信度经过校验，非法结果或异常会退回 `OTHER`；证据中不写服务异常原文，避免带入敏感信息。

当前没有连接真实模型客户端，默认 `fallback=None`，所以规则无法判定的条款仍为 `OTHER`。测试中的兜底函数只验证接口和失败处理，不代表完成了真实 LLM 归类。PRD 的模型归类要求、结构化节点中的分类比例统计和任务降级提示仍需后续接入。
