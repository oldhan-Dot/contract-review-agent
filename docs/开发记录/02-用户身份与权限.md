# 模块 02：用户身份与权限

> 模块开发记录，保留当时的实现与验证状态。当前需求以 [PRD](../PRD.md) 为准，技术实现以 [Spec](../SPEC.md) 为准；历史章节号不作为当前规范。

本轮新增 `GET /api/users/me`，完成请求头格式校验、数据库身份确认、角色限制和任务访问权限。用户数据使用 Pydantic 响应模型输出。

## 阅读顺序

1. `app/schemas/user.py`：允许的角色与用户响应字段。
2. `app/core/security.py`：请求头解析、用户确认、角色限制、任务权限。
3. `app/core/errors.py`：将错误转换成统一 JSON。
4. `app/schemas/common.py`：成功响应和错误响应的数据结构。
5. `app/api/users.py`：通过 `Depends` 使用校验结果，返回当前用户。
6. `app/main.py`：注册业务路由和错误处理。

## 为什么先校验格式，再查数据库

`parse_identity_headers()` 使用 FastAPI `Header` 声明用户 ID 和角色：

- 用户 ID 必须为正整数，且不能超出 MySQL 无符号 BIGINT 范围。
- 角色只能是 `LEGAL`、`BIZ` 或 `ADMIN`，区分大小写。
- 有值但格式不合法返回 422，不调用数据库查询。
- 缺少任一身份头按 PRD 返回 401。

格式通过后，`get_current_user()` 调用 `resolve_user()` 查询用户。不存在或已停用的用户返回 401；请求角色与数据库记录不一致返回 403。

例如，一个业务用户传入 `ADMIN`：这个角色字符串的格式合法，但数据库身份校验会拒绝它。格式合法与权限合法是两件事。

本模块的请求数据在 HTTP 请求头中，因此直接用 `Header` 校验；后续 JSON 请求体再定义对应的 Pydantic 请求模型。数据库 ORM、接口数据模型和权限依赖分别负责存储、格式与业务规则。

## 当前用户接口

```http
GET /api/users/me
X-User-Id: 1
X-User-Role: LEGAL
```

当前本机预置法务用户的响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": 1,
    "username": "legal",
    "display_name": "法务审查人",
    "role_code": "LEGAL",
    "company_name": "示例企业有限公司",
    "is_active": true
  }
}
```

`response_model=ApiResponse[UserOut]` 限制字段和类型，不把整个 ORM 对象或数据库列直接输出。前端只接收 `UserOut` 中声明的六个字段。

PowerShell 调用示例：

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/users/me' -Headers @{
    'X-User-Id' = '1'
    'X-User-Role' = 'LEGAL'
}
```

也可以在 `/docs` 的“用户身份”分类中打开接口，使用 Try it out 填写两个请求头。

## 任务与角色权限

`require_task_access()` 先校验任务 ID 和身份头，再确认用户。业务人员的查询在 SQL 中增加 `applicant_id = 当前用户ID`，法务与管理员可访问全部未删除任务。

业务人员查不到授权任务时，只再查询目标任务 ID，区分“他人任务”与“不存在/已删除”，分别返回 403 和 404，不先读取他人的完整任务。

`require_roles("LEGAL")` 等依赖用于限制具体功能。管理员不会自动绕过角色要求，例如 PRD 中审批回写仅允许法务执行。

数据库查询会开启 Session 事务。后续请求方法可以在当前事务中写入并显式 `commit()`；若需要 `with session.begin()` 的独立短事务，应使用新会话，不在已经查过数据库的会话上重复 begin。

## 错误返回

| 情况 | HTTP 状态 | 业务码 |
| --- | --- | --- |
| 身份头缺失、用户不存在或已停用 | 401 | 40100 |
| ID 或角色格式错误 | 422 | 40001 |
| 角色不匹配、权限不足 | 403 | 40300 |
| 任务不存在或已删除 | 404 | 40401 |

失败响应包含 `code`、`message`、`data: null`。格式错误额外提供 `errors` 字段列表，只说明字段位置和原因，不回显原始输入、请求体或异常上下文。

本轮明确保留 FastAPI 的格式错误 HTTP 422；PRD 错误码表中 40001 对应 HTTP 400，这里使用同一业务码配合 422，并保留字段错误列表，便于前端定位问题。

## 验证结果

```powershell
. ./scripts/common.ps1
uv run --locked python -m pytest tests --run-db-tests -q
```

**37 项通过**：15 项无需数据库的格式测试、18 项新增真实 MySQL 身份与权限测试、4 项已有模型测试。

格式测试使用禁止查询的数据库替身：一旦格式不合法的请求触发查库，测试立即失败。数据库测试仍在外层回滚事务中运行，不保留测试用户和任务。

本机运行中的后端已验证 200/401/422 响应，OpenAPI 已包含新接口，前端 Vite 的 `/api` 代理可以访问它。

## 本轮边界

生产应用新增接口只有 `/api/users/me`。用于验证任务权限和法务专属权限的 `/test/...` 路由只存在于测试应用，未加入实际服务。

这里仍是课程项目的演示身份头，无法防止伪造另一个合法用户的 ID 和角色。正式登录认证需在后续有明确需求时改为密码登录与服务端签发的 Token。
