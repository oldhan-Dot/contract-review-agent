# 日期与期限提取

本模块按技术方案 6.3.1 实现五个字段：履行开始日期、履行结束日期、合同期限天数、生效条件、签署日期。输入仍是 DOCX 的 `ParsedDocument`，不读取文件、不查询数据库、不调用模型；尚未接入 `structure_document` 节点。

## 建议阅读顺序

1. `app/structuring/date_metadata.py` 的 `extract_date_metadata`：整个模块入口，先看三个步骤及输出字段。
2. `_date_candidate`、`_field`：日期合法性、标准值、候选选择和原文位置。
3. `_signature_dates`：如何识别签署标签、签章段落及紧邻日期行。
4. `_durations`、`_period_days`：期限识别、日历换算和起止日期互校。
5. `app/structuring/metadata.py` 的 `extract_metadata`：组合主体、金额和日期结果，不覆盖已经提取的其他字段。

## 识别与校验

| 字段 | 本次行为 |
|---|---|
| `perform_start_date` | 识别明确的开始日期标签，或合同期限语境中的日期区间、开放起点 |
| `perform_end_date` | 识别明确的结束日期标签，或同类语境中的区间终点、开放终点 |
| `contract_period_days` | 优先使用合法起止日期差；没有完整区间时使用明确文字期限，能可靠换算才输出天数 |
| `effective_condition` | 按技术方案保留含“生效”的段落；最多 200 字，超长时截取包含关键词的片段并提示 |
| `sign_date` | 在签署标签或明确签章区内取最后一个日期；不同候选及早于五年前的日期提示人工核对 |

支持阿拉伯数字中文日期、`YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY.MM.DD`，以及全角数字、中文日期中的空格。标准值统一为 `YYYY-MM-DD`，证据保留原始写法。中文汉字数字日期、缺少年份及混合分隔符不会猜测补全。

用 `datetime.date` 校验闰年、月份和实际天数。识别到但不合法的公历日期保留观察值、真实原文位置及警告，置信度降到 0.3；未匹配到完整日期则保持缺失。开始晚于结束时保留两端，不交换日期，也不推导负数期限。

付款、交付等标签及报价、质保有效期不作为合同履行期限。只有明确期限语境才提取期限数字，不从全文任意“30 日”推断。

## 天数怎么计算

原文：`合同期限：2026年1月1日至2026年1月31日，共90日`

输出起点 `2026-01-01`、终点 `2026-01-31`、期限 `30`，并提示文字期限与日期差不一致。派生期限的证据覆盖两个日期，原始候选保留区间及 `90日`。

- 使用 `(end - start).days`，即日期差，不自动额外加一天；同日区间为 0。遇到文字期限差异会提示核对是否包含首尾日。
- “30 个自然日”“90 天”直接提取天数；明确的零或负数文字期限保留并提示。
- 月、年需要已知起始日期，按公历同月同日或对应月份同日计算。例如 2024-02-01 起一个月是 29 天。
- 不把月固定算 30 天，也不把年固定算 365 天。缺少起点、月末或闰日找不到对应日期时不换算，保留原始期限和提示，不擅自取月末。
- 工作日需要节假日日历，本次不换算；保留原文和提示。
- 相对期限不会用今天或签署日期生成原文未写出的履行起止日期。

## 签署日期和原文证据

DOCX 解析结果没有可靠页码，因此用明确签署标签，或“甲方（盖章）”等签章段落与紧邻的纯日期行作为签署区线索，不取全文最后一个任意日期。多个不同签署日期按方案取最后一个并提示人工核对。

`extract_date_metadata(document, today=...)` 和组合入口均允许注入今天的日期，便于复现五年边界测试；不传时使用服务器当天日期。五年规则仅作校验提示，不丢弃历史合同日期，也不等于判定合同无效。

非缺失字段均使用 `Anchor.from_document_range` 生成真实证据，返回前执行 `validate_against_document`。缺失字段无标准值及 Anchor。原始候选采用有效 JSON，最多保存 10 条、每条前 200 字符及完整区间，总长度不超过 1024；完整原文仍在解析结果中。
