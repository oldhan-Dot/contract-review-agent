# 模块 03：合同上传与任务创建

历史记录说明：本页描述旧版上传行为。重整后必填字段、上传权限与去重条件已调整，当前行为见 [18-送审信息与上传权限调整](18-送审信息与上传权限调整.md)，不要再按下文默认 UNKNOWN/甲方调用。

本模块新增 `POST /api/tasks/upload`，把合法 DOCX 保存到 `data/uploads/{task_id}/{task_id}_1.docx`，同时写入 `contract_task` 和 `contract_file`。任务初始状态为 `pending`；解析和审查由后续模块接入。当前版本开发清单选择先跑通 DOCX，PDF 和图片上传仍待后续实现。

## 输入和处理顺序

请求使用 `multipart/form-data`，身份头仍是 `X-User-Id`、`X-User-Role`。字段包含必填的 `file`、`contract_name`，以及可选的 `contract_type`、`amount`、`currency`、`our_party_role`、`applicant_dept`。`contract_type` 默认 `UNKNOWN`，我方角色默认 `A`。金额采用十进制数，最多 18 位、小数最多两位。

FastAPI 先校验请求头与表单格式，方法中再检查空白合同名称、文件名和 `.docx` 后缀，随后调用 `resolve_user` 查询数据库确认用户。文件按 1MB 分块读取并累计大小；小于 1KB 返回 40001，超过 50MB 返回 HTTP 413 / 41301。随后检查 ZIP 容器内的 `[Content_Types].xml` 和 `word/document.xml`，伪装 DOCX 返回 HTTP 415 / 41501。

文件先写入 `uploads` 目录下的随机临时文件。通过校验后，按申请人和 MD5 查询历史上传；重复文件复用已有任务，返回 `duplicated=true`。同一申请人的上传在数据库中按用户行锁串行化，避免并发重复提交产生多个任务。新任务取得 ID 后，原件移动到服务端生成的路径，文件记录与任务一起提交。写入失败会回滚数据库并删除新文件。原始文件名仅用于数据库展示字段，不进入磁盘路径。

## 请求示例

```powershell
curl.exe -X POST http://127.0.0.1:8000/api/tasks/upload `
  -H "X-User-Id: 2" -H "X-User-Role: BIZ" `
  -F "contract_name=采购合同" -F "contract_type=PURCHASE" `
  -F "amount=12500.00" -F "file=@D:\contracts\purchase.docx"
```

成功返回 HTTP 201：

```json
{"code":0,"message":"ok","data":{"task_id":1,"task_no":"UP-...","status":"pending","duplicated":false}}
```
