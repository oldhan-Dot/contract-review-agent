# 模块 08：条款数据结构与原文校验

新增 `app/structuring/models.py`，按照技术方案第 6.5 节定义条款 `Clause`。它是结构化节点的处理结果模型，不是数据库表映射。本次不执行切分、提取字段或归类，也不改变 LangGraph 节点行为。

## 段落与条款的区别

解析段落对应 Word 的排版单元，条款对应一次可以审查的合同约定。一条条款可以包含标题段落和多个正文段落；较长段落也可能需要切成多条子条款。

例如原文两个段落是「第一条 付款」和「甲方应在验收后付款。」：

- 条款 `clause_no` 为「第一条」，`title` 为「付款」。
- 条款 `text` 为 `付款\n甲方应在验收后付款。`，去掉编号和首尾空白，供审查阅读。
- 原文区间仍覆盖 `第一条 付款\n甲方应在验收后付款。`，用于定位和证据核对。

因此 `text` 长度不要求等于原文区间长度。定位时调用 `source_text(document)`，不能直接把 `text` 当作原文。

## 字段分组

| 字段 | 用途 |
|---|---|
| `index`、`clause_no`、`level`、`title`、`text` | 顺序号、原文编号、层级、标题和正文 |
| `paragraph_index_start/end`、`char_start/end`、`page_start/end` | 记录对应原文的段落、字符区间及可用页码 |
| `split_strategy` | 记录按编号、样式、伪标题或长度兜底切分 |
| `parent_index`、`part_no` | 记录父条款与长条款拆分出的子条款编号 |
| `clause_type`、`clause_type_secondary`、`type_confidence`、`classify_rule_hit` | 预留归类结果与依据 |

按技术方案，条款顺序号从 **1** 开始，解析段落顺序号从 **0** 开始。起止段落编号都包含在内；字符区间左闭右开。DOCX 不填写页码，PDF/OCR 的页码字段为后续格式预留。

`ClauseType` 定义 PRD 第 8.1 节的十二类条款及 `OTHER`；默认 `OTHER` 表示尚未归类，不代表分类算法已经执行。

## 两层校验

构造 `Clause` 时自动校验字段与关系：正文非空、区间有效、段落和页码起止合理、父条款不能指向自己、拆分子条款具有父编号、次类型不同于主类型。

切分器构造结果后，还需要显式调用 `clause.validate_against_document(document)`，检查其引用的段落存在、字符位置位于对应段落内、页码正确，以及从原文移除编号和首尾空白后得到的正文与 `text` 一致。该方法需要实际 `ParsedDocument`，所以不在仅构造条款时自动运行。

父条款是否存在于完整条款列表、条款是否漏文或顺序是否完整，要在下一步切分器输出整组结果时检查，本模块只检查单条结构。
