# 结构化节点接入

> 模块开发记录，保留当时的实现与验证状态。当前需求以 [PRD](../PRD.md) 为准，技术实现以 [Spec](../SPEC.md) 为准；历史章节号不作为当前规范。

本次把已经完成的条款切分、规则归类和字段提取接入 `structure_document`。节点不查询数据库、不读取上传文件、不调用真实模型，也不写任务状态或审查结果。

## 先看哪两个文件

| 文件 | 作用 |
|---|---|
| `app/graph/state.py` | 增加共享字段 `clauses`、`metadata`、可选 `task_name` |
| `app/graph/nodes/structure_document.py` | 在一个节点函数内按步骤调用现有模块 |

没有再定义一套条款或字段结构：`clauses` 使用 `list[Clause]`，`metadata` 使用已有 `MetadataResult`。State 负责把结果传给后续节点，数据模型负责表达和校验具体内容。

## 节点中的五步

1. 检查 `document` 是 `ParsedDocument`、文件 ID 与执行参数一致、格式为 DOCX，以及可选任务名是字符串。上游解析节点仍负责查询任务与原件归属、版本校验；这里不重复查库。
2. `split_clauses(document)`：产生条款列表，保留原文区间、父子关系及超长条款子段。
3. `classify_clauses(clauses)`：按现有标题、关键词和父类型规则归类，记录置信度及判定依据；本次不传模型兜底函数。
4. `extract_metadata(document, task_name=...)`：从完整解析原文提取名称、编号、主体、金额、币种、日期等字段。这里使用完整原文，避免条款边界破坏主体区段或金额配对。
5. 全部成功后返回 `{"clauses": clauses, "metadata": metadata}`。LangGraph 合并增量状态，再执行 `rule_review`。

原文 `document` 继续保留在 State 中。节点不把输入 State 整体返回，也不就地改写原文或输入字段；`clauses` 和 `metadata` 使用覆盖更新，重跑同一输入不会追加重复条款。

## 状态中的结果怎么读取

```python
clauses = state["clauses"]
for clause in clauses:
    print(clause.clause_type, clause.text)

metadata = state["metadata"]
amount = metadata.get("amount")
# 后续规则需要先判断 amount 是否存在、是否缺失，以及是否有校验警告。
```

`MetadataResult.items` 内是完整字段目录，不代表每项都被识别到。每项仍包含缺失状态、原文值、置信度、警告与原文位置。

`task_name` 仅在调用入口显式传入时参与标题兜底；本次没有修改解析节点为它追加数据库查询，也没有让上传接口自动执行图。

## 失败和未识别如何处理

- 缺少解析结果、串文件、非法执行参数明确拒绝；不支持格式抛出 `ParseBlocked("UNSUPPORTED_FORMAT", ...)`。
- 空正文保留切分器的 `EMPTY_BODY` 原因。切分、归类或提取发生异常时直接中止，不返回部分更新，不继续执行后续步骤。
- 普通字段缺失、非法观察值的核对提示、归类不能确定时的 `OTHER` 按现有模块保留，不因此使结构化节点失败。
- `OTHER` 不是“没有风险”。分类依据中的 `needs_fallback` 仍在，后续规则/执行器需据此处理覆盖缺口。
- 本节点不覆盖已有 `review_degraded`、`review_degraded_reason` 等状态，也不提前宣称规则或 AI 审查完成。
