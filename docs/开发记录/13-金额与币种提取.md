# 金额与币种提取

本次实现 DOCX 解析结果中的合同总金额、币种、大写金额及大写金额数值提取。不读取上传文件，不调用模型，不写数据库，尚未接入 `structure_document` 节点。

## 建议阅读顺序

1. `app/structuring/cn_num.py`：`cn_amount_to_decimal` 将中文金额转换成 `Decimal`，无法确定时返回 `None`。
2. `app/structuring/money_metadata.py`：`extract_money_metadata` 负责定位候选、选择金额、校验及构造证据。
3. `app/structuring/metadata.py`：`extract_metadata` 组合主体与金额结果，保留双方名称和信用代码；日期等未完成字段仍标为缺失。

## 处理步骤

1. 按换行、中文句号和分号划分金额语境，搜索数字及中文金额。
2. 根据明确金额标签区分总额与预付款、定金、尾款、违约金、保证金、单价等分项。存在总额标签时优先保留总额候选；只有明确分项的金额不会填成合同总额。无总额标签时允许使用带金额单位或币种的候选。
3. 数字金额优先，大写金额兜底。同类多个候选按最早位置选择，同位置取长者；值不同则给出人工核对提示。
4. 使用 `Decimal` 计算，支持规范千分位、全角数字和万/亿单位；不修复错误千分位，也不把超过两位小数静默舍入。检查金额大于 0 且不超过 10^12。非法观察值低置信度保留并提示，不能转换的大写金额保留文字，其派生数值留空。
5. 识别所选金额附近的 CNY、USD、EUR、HKD 及对应符号/中文单位；`HK$` 优先于 `$`。无邻近标记时可使用明确的“币种：USD”等声明，否则保持币种未识别。
6. 仅比较所选数字金额同一语境内的大写金额，差额超过 0.01 时提示不一致；明确币种不同时提示币种冲突。这里只生成字段警告，尚未生成风险项。
7. 通过 `Anchor.from_document_range` 保留实际原文区间，并调用 `validate_against_document` 核对证据。

## 输出示例

原文：`合同总金额：人民币壹佰贰拾万元整（¥1,200,000.00）`

| 字段 | 标准值 |
|---|---|
| `amount` | `1200000.00` |
| `currency` | `CNY` |
| `amount_in_words` | `壹佰贰拾万元整` |
| `amount_in_words_value` | `1200000.00` |

`amount_in_words_value` 是为 PRD 的 R-AMT-04 补充的派生字段。原有 14 项目录加上该字段，现在共 15 项。没有新增数据库列，尚未执行字段入库。

标准值允许与原文写法不同，例如金额的证据仍是 `1,200,000.00`。原始候选以 JSON 写入 `field_value_raw`：最多尝试保存 10 条，每条保留前 160 字符和完整区间；总长度超过 1024 时减少条数。完整原文仍保存在解析结果中。

## 当前边界

- 这是规则提取，不保证识别所有自然语言金额表达；未覆盖的合同写法需要补充样本。
- 不支持跨段落、跨表格单元格配对金额和大写金额，也不比较不同语境中的金额。日期、人民币以外的中文货币细分单位及汇率换算尚未实现。
- “一千二”“一万二”等有省略歧义的中文金额不猜测数值。
- 没有金额不会阻塞提取，返回缺失状态和人工补充提示；缺失币种不默认人民币。
- 日期提取、结构化节点接入及字段持久化留待后续逐步实现。
