本轮根据“系统有点复杂，先看整体效果”的反馈，收紧当前开发范围，优先让已有流程容易理解和操作。

## 当前先做什么

先使用已有“上传 → 自动审查 → 原文核对 → 法务确认 → 导出报告 / 演示回写”。批量、完整规则模板管理、审批 HTTP 集成、重传审计等暂缓，最终要求仍保留在唯一的 [PRD](../PRD.md) 和 [Spec](../SPEC.md)。已有实现和数据保留。

`nextStep` 只是基于已有数据计算提示语，不增加新的业务状态。阶段映射不改变 LangGraph 的节点名称。

## 演示回写如何执行

1. 法务核对风险、编辑建议和补充意见。
2. 点击“确认本次审查”，后端保存并确认当前意见版本。
3. 点击“演示回写”。如果还没有审批单，先调用现有 `mock-approval` 接口关联，再调用 `writeback`。
4. 成功后通过“查看模拟评论”核对结果，也可以使用原有报告导出入口。

前端在发起操作时记录审查版本与意见修订号，后端继续检查权限、完整性、确认和版本；合并按钮不绕过这些检查。两个请求分别提交，关联成功后回写失败可以再次操作，后端保持幂等。这里只写本系统数据库内的模拟评论，不连接真实审批平台。
