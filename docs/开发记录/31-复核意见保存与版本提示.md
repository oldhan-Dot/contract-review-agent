# 31. 复核意见保存与版本提示

本轮继续完善已有复核操作，不扩展新模块。代码集中在 `frontend/src/views/ReviewView.vue`。

## 解决的问题

| 问题 | 调整后 |
|---|---|
| 没改意见也能保存草稿，后端会撤销已有确认 | 只有存在未保存修改时才允许保存草稿，方法入口也检查该条件 |
| 保存请求尚未结束时继续编辑，可能误以为新输入已被保存 | 保存等操作执行期间，建议与补充意见暂时只读，失败后恢复编辑 |
| 改完直接导出，容易误以为报告包含未保存内容 | 有未保存修改时，明确提示预览、导出和模拟评论使用已保存内容 |
| 重审后修订号可能相同，仅比较修订号无法发现旧草稿 | 同时比较审查版本和意见修订号，变化时禁用保存、确认及回写，提示重新载入 |
| 重新载入会丢弃本地草稿，提示不够清晰 | 按钮旁明确说明将放弃未保存修改 |

## 代码如何处理版本

`editingVersion` 记录加载草稿时对应的 `review_version`，`editingRevision` 记录同一次加载的意见修订号。保存时提交这两个基准值，由后端继续执行原有权限、完整性和版本校验。

例如，旧草稿对应审查版本 1、修订号 0；重审后结果变为版本 2、修订号 0。即使修订号相同，前端仍能识别当前草稿属于旧审查。用户重新载入后，再基于新结果修改意见。

本轮没有新增数据库字段、接口或业务状态。前端提示和禁用按钮用于减少误操作，最终校验仍由后端负责。

## 必要验证

- `npm run build` 通过。
- 本机无窗口 Edge 打开合成任务 489：未编辑时草稿按钮禁用；修改后按钮启用并出现报告内容提示。
- 在浏览器内暂停保存请求，确认编辑框暂时只读；返回模拟 409 后，未保存内容保留、可继续编辑。
- 仅在浏览器返回数据中增加审查版本，保持修订号不变，确认旧草稿的保存和确认按钮禁用，出现重新载入提示；重新载入恢复已保存意见。
- 浏览器运行时异常为 0。本轮验证未发送实际 PATCH，不改动已保存的意见，没有模型/OCR 调用，未执行全量回归。

这次检查验证的是界面操作保护；后端真实保存、确认和模拟回写的既有联调记录见第 25、30 篇。未提交或推送 Git。
