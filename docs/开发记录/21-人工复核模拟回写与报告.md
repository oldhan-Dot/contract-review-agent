## 接口与操作

| 接口 | 用途 |
|---|---|
| GET /api/tasks、/api/tasks/{id} | 按权限查询列表、统计和当前版本结果 |
| PATCH /api/tasks/{id}/review | 法务保存建议、补充意见或确认 |
| POST /api/tasks/{id}/retry | 管理员重新审查 |
| POST /api/tasks/{id}/mock-approval | 开发演示中关联模拟审批单 |
| POST /api/tasks/{id}/writeback | 法务将已确认意见写入模拟评论 |
| GET /api/tasks/{id}/comments | 查看对应模拟审批评论 |
| GET /api/tasks/{id}/report | 预览或下载 Markdown/PDF |
| GET/PATCH /api/rules[/{code}] | 法务查看规则；管理员调整首版配置 |

业务身份仅查看自己的任务，法务/管理员可查看全部。管理员不能代替法务确认。

## 人工意见与并发

保存请求携带 review_version、expected_revision。后端锁定任务与当前快照并检查版本，旧页面提交返回 409，不覆盖其他人的意见。

部分审查结果允许保存草稿，完整确认必须满足 completed 和 complete；每项风险都需要最终建议。再次编辑会取消原确认并重置回写状态。

## 回写和报告

当前模拟回写直接在同一数据库事务写入 mock_comment、mock_idempotency，使用任务、版本、报告内容生成幂等键。重复回写相同内容返回同一评论 ID。没有连接外部审批平台；外部 HTTP 适配、审批事件接入后续完成。

`app/services/reports.py` 为报告和回写共用 Markdown，使用已保存数据，不重新生成另一套结论。部分结果、未确认状态、依据待核验会保留在报告中。

PDF 使用 PyMuPDF 内置中文字体换行分页，无需安装 Word。该能力是“生成审查报告”，合同原件 DOCX 转 PDF 预览仍待后续处理。
